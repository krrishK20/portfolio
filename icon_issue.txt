## **What Needs to Be Fixed & Why**

### **1. ALL 14 Icons Require Immediate Fixing**
Every single icon asset is failing to load. This is not isolated to one or two icons—it is a **systemic failure** affecting the entire iconography system.

### **2. Root Causes to Address:**

**Primary Suspect: Missing Icon Font File**
- The pattern suggests use of an icon font (like Font Awesome, Devicons, or Simple Line Icons) where CSS classes map to private-use Unicode characters (e.g., `\fXXX`)
- **Fix:** Ensure the `.woff2`, `.woff`, or `.ttf` font file is correctly referenced in `@font-face` declarations and the file path is accessible

**Secondary Suspect: Character Encoding Mismatch**
- The specific characters shown (`ö`, `Ý`, `š`, `€`) suggest UTF-8 bytes being interpreted as ISO-8859-1 or Windows-1252
- **Fix:** Ensure `<meta charset="UTF-8">` is present, and server headers specify `Content-Type: text/html; charset=utf-8`

**Tertiary Suspect: CDN/Asset Loading Failure**
- If using external icon libraries (CDN), the request may be blocked by CORS, ad-blockers, or network issues
- **Fix:** Check browser console for 404 errors on font files; consider self-hosting icons

### **3. Specific Attention Required:**
- **Metasploit Card**: Currently has active focus state (blue border) but no visual icon feedback—user experience confusion
- **Docker Card**: Appears to have a background container element working, but the inner glyph is corrupted—suggests partial loading or fallback failure
- **Nmap Card**: Shows different corruption pattern (`âš` vs `öÝ`) suggesting possible inconsistent encoding sources or copy-paste errors in the HTML/CSS

### **4. Recommended Solution:**
Replace the icon font system with **SVG inline icons** or **PNG/WebP images** for these specific security tools, as icon fonts are prone to FOIT (Flash of Invisible Text) and encoding failures. Alternatively, fix the `@font-face` declaration to properly load the cybersecurity icon set (likely [Devicons](https://devicon.dev/) or similar).
